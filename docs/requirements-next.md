# HanziGo 下一批改进 —— 需求

写于 2026-10-04。来源：把 HanziGo 现有功能跟 phase-6、Anki、Duolingo 三个产品比了一遍，
看哪些差距对「一个在瑞典上四年级、母语中文的孩子」真的有影响。

## 比较的结论

三个参照物里 **phase-6 最接近**我们的处境：词汇绑定具体课本、给具体孩子用、家长在旁边看。
Anki 是通用 SRS 引擎，Duolingo 是面向大众的自学产品，两者都不假设「周五有听写」。

读代码后确认 HanziGo **已经有的**（README 里没写）：

- `SpacedRepService`（services.js:491）—— 5 盒 Leitner，间隔 `[0,1,3,7,14]` 天
- 四种题型 `pickPinyin` / `pickChar` / `fillBlank` / `pickWord`
- 多用户 profile，各自独立 localStorage 命名空间，含旧数据迁移
- 每日任务五步 `review → recap → learn → quiz → done`
- 成长徽章 50/100/200/500/1000/2000 字，连续天数里程碑
- service worker 缓存失效正确（`CACHE_VERSION` + `skipWaiting` + 清旧缓存）
- 按课筛选 `lessonFilter` → `filteredChars` → `generateQuizQuestions` 已打通

所以算法本身不落后，差距在**算法周围**：孩子能瞄准什么，家长能看见什么。

## 不做的事（明确排除）

| 不做 | 原因 |
|---|---|
| 积分、皮肤、头像、吉祥物 | 已有徽章和连续天数，够了。用户是一个每天能说话的孩子，不是留存指标 |
| 排行榜、宝石 | 同上；且会引入跟自己比之外的比较 |
| 手写识别 | phase-6 卖笔，我们不卖；成本远超收益 |
| 云同步（`docs/cloud-sync-proposal.html`） | 会把一个无后端、无构建、4375 行的东西变成要运维的服务。一个孩子一台设备，localStorage 就是对的 |
| AI 答案分析 | 解决的是自由文本语法问题，我们没有 |
| 订阅/功能分级 | 自用 |

## R1 — 考试模式（听写准备）

**问题**：学校的听写在周五，不管 SRS 认为这些字到不到期。现在要达到「只练这一课」，
家长得先进学习模式、拉 `lessonFilter`、再切到挑战模式 —— 孩子自己不会做这一串。

**已有**：`generateQuizQuestions` 用 `filteredChars`，`lessonFilter` 设的就是它。逻辑齐了，缺入口。

**要做**：一个明确的入口 —— 选年级学期 → 选课 → 只考这课的字 → 全对才算过。

验收：
- 选定某课后，出的题目全部来自该课
- 题目数 = 该课字数（不受 `questionsPerRound` 的 10 限制）
- 结果显示「本课 X/Y 字」，错的字列出来
- 不污染 SRS 的到期计算（考试模式答题仍记入 SRS，但不改变每日任务的 10 个上限）
- 入口在主界面可见，不藏在筛选器里

## R2 — 家长视角（只读一屏）

**问题**：代码里完全没有家长相关的东西（grep `parent` / `报告` / `dashboard` 均无）。
家长现在看不见孩子哪里卡住，只能借设备翻。

**已有**：`SpacedRepService.getBoxStats()` 盒子分布、`getDueCount()`、`getTotalCount()`，
错题本每字带 `wrongCount`。数据全在，缺呈现。

**要做**：一屏只读页面，显示

- 盒子分布（box1..box5 各多少字）
- 卡在 box 1 的字（学了但一直没记住的）
- 错得最多的前 10 个字及错误次数
- 本周完成了几天每日任务
- 当前进度：几年级第几学期第几课

验收：
- 纯读，不提供任何修改入口
- 不需要密码（自用，加密码只会让自己也进不去）
- 空数据时显示「还没有数据」而不是报错或空白

## R3 — 间隔上限从 14 天加长

**问题**：`BOX_INTERVALS = [0,1,3,7,14]`，上限 14 天。4014 个字，一年级学的字会永远每两周
回来一次。每天复习上限 10 个（`getReviewChars` 的 `MAX_REVIEW`），积压是算术必然，不是可能。

**要做**：`BOX_INTERVALS = [0,1,3,7,14,30,60]`，box 上限从 4 改到 6。

验收：
- 盒子数与间隔数组长度一致，无越界
- 已有 SRS 数据（box 0..4）升级后不丢、不错位
- box 5/6 的字到期判断正确（30/60 天）
- 现有 SRS 测试全部仍通过

## R4 — 答错不归零，改为降一级

**问题**：`services.js:541` 现在 `data[char].box = 0`。一个进了 box 5 的熟字，手滑错一次
回到起点，要重爬 14 天。对孩子是「我明明会」的挫败感。Anki 的做法是掉一级而非归零。

**要做**：`box = Math.max(0, box - 1)`。

验收：
- box 3 答错 → box 2，不是 0
- box 0 答错 → 仍是 0，不出现负数
- 答错仍进错题本（两个机制独立，互不影响）
- 现有「答错降级」测试需同步更新预期值

## R5 — 连续天数宽限日

**问题**：`consecutiveDays` 断一天就从 1 重算。瑞典学校有 höstlov、jullov、sportlov，
加上生病 —— 40 天的记录几乎注定会断，断了孩子就不想续。

**要做**：允许断一天不清零（第二天补上即可延续）。不做成道具或消耗品。

验收：
- 隔一天回来：连续天数继续累加，不重置
- 隔两天及以上：重置为 1
- 同一天多次打开不重复累加
- 跨月、跨年边界正确

## R6 — 拼音输入题型

**问题**：四种题型全是选择题。中文的「认得」和「写得出」差距比欧洲语言大 —— 孩子能从四个
选项里挑出「塘」，但未必写得出 `táng`。phase-6 要求打字正是为此。

**要做**：第五种题型「看字输入拼音」。输入不带声调的字母即可（`tang` 算对），声调另算加分项。

验收：
- 输入 `tang` 对「塘」判对；`tāng` 等声调变体也判对
- 多音字按当前词条的读音判
- 移动端唤起的是字母键盘
- 可在 `quizTypeSelector` 里单独选，也参与 `mixed`

## R8 — 自定义字卡

**需求来源**：用户 2026-10-04 提出。课本之外也有要记的词 —— 故事里看到的、瑞典语课上的、人名。

**为什么是三个输入框而不是两个**：卡片不是两面，是四个字段
（`char` / `pinyin` / `words[]` / `sentence`）。两个输入框只能填 `char` 和一团文本，
结果是卡片能翻但**不能出题** —— 四种题型分别读 `pinyin`（字→音、音→字）、
`words[]`（字→词）、`sentence`（填空）。加一个拼音框就解锁两种题型，成本是一个框。

正面 → `char`，拼音 → `pinyin`，反面 → `sentence`（卡片背面本来就渲染这个字段）。
`words` 留空，所以字→词会跳过这些卡（`getRandomWordDistractors` 本来就过滤空 words）。

**存在哪**：自己的 key `customCards`，按 profile 隔离。**不能**放进 `data/*.json` ——
那些是从课本 PDF 生成的，重新生成会把用户内容冲掉。

**位置**：侧边栏「智能复习」下面，✏️ 自定义字卡。点它开编辑面板（不是直接进学习）——
零张时如果直接进学习，就没有任何入口能建第一张卡。

验收：
- 三个输入框：正面（≤8 字）、拼音（可空）、反面（≤200 字）
- 正面或反面为空、正面重复、超长 → 报错且不保存，**已填内容不丢**
- 输入自动 trim
- 卡片形状与课本字一致（`grade`/`semester` 为 0 标记非课本来源），下游无需特判
- 缺 `pinyin`/`words` 不能让卡片渲染崩
- 正面多字时字号自动缩小
- 侧边栏计数跟随；**零张也不 disable**
- 存储损坏（不是数组）时降级为空，不抛异常
- 渲染时转义，存进去的 HTML 不执行
- 「复习卡片」进入学习模式，而不是回到编辑面板

不做：编辑已有卡片（先有增删列表，编辑是第二屏）。

## R7 — 每个字自己的难度系数（暂不做）

同一个 box 里的字间隔也该不同 —— 这孩子觉得「塘」简单、「虑」要命，现在都是 3 天。
这是 Anki 真正的优势。

**但 R1–R6 做完再评估**。成本中等，且前六项做完后可能发现不需要。

## 实施顺序

1. **R3 + R4** —— 同一个文件（`services.js`）同一块逻辑，一起改一起测
2. **R5** —— 独立，小
3. **R1** —— 接现成数据，不动算法
4. **R2** —— 接现成数据，纯新增页面
5. **R6** —— 新题型，动 `data.js` 和 UI
6. **R7** —— 重新评估后再定

R3/R4 排最前是因为它们改的是**已有数据的语义**，越晚改、积累的 SRS 数据越多、迁移越麻烦。

## 测试要求

每项改动都要在 `test.html` 补测试并全绿。现状基线：

- `test.html` —— 28 组、135 个 `it()`，用隐藏 iframe 加载真实 app
- `pre-push.sh` —— 15 项静态检查（Python），推送前自动跑

规矩：

- 改了行为就改测试的预期值，不是放宽断言
- 每项需求至少覆盖：正常路径、边界、空数据
- R3/R4 要专门测**旧数据迁移**（已有 box 0..4 的数据升级后不错位）
- 提交前 `test.html` 全绿 + `pre-push.sh` 15 项全过
